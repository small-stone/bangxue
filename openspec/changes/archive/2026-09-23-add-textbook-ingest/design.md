# Design

## Context

见 `proposal.md`。Postgres 已在本机运行（库 `bangxue`，扩展 `vector` 0.8.6）。`apps/api` 尚无数据库访问代码。本地 `book/小学/数学/人教版/` 已有多册 PDF，且 `book/` 目前未被 git 忽略。

入库是离线批处理，不是家长请求路径。出题图仍留在 `agents/textbook/`，本 change 不实现它。

## Goals / Non-Goals

**Goals:**

- `apps/api/ingest/` 一个包：解析、按单元拆分、embedding、写入 pgvector
- 命令行参数表达「这一本是谁」，代码不写死某一册
- 用一年级上册证明「按单元能查回该单元」
- 需求文档与 `.gitignore` 和上述行为一致

**Non-Goals:**

- 本次不把其余册次全部入库（命令可用即可）
- 不做出题、确认、PDF 或 Jev
- 不把教材 PDF 放进对象存储（本地路径足够）
- 解析失败时不自动切换到付费解析服务；先把失败暴露出来

## Decisions

### 1. 目录

```
apps/api/ingest/
  __init__.py
  cli.py          # 参数：pdf、学段、年级、科目、版本、学期
  parse.py        # PDF → 带页码的文本
  split.py        # 按单元标题切开
  store.py        # 删旧块、写新块与向量
```

- **选择**：`apps/api/ingest/`，与 API 共用 Python 环境，但是 `python -m ingest` 一类命令，不注册 HTTP 路由
- **备选**：放进 `agents/textbook/` — 拒绝，出题图和批处理会缠在一起
- **备选**：仓库根目录单独一个应用 — 拒绝，一期不必为入库再加一个可部署单元

### 2. 切分

先用 pdfplumber 抽取文本和页码。以教材目录或正文中的单元标题（如「第 X 单元」）作为切分点。块上保存：单元名、起止页、正文、五元组元数据。

一年级上册若抽不出单元标题，命令失败并打印样例页，再决定要不要为这一版式加一条标题规则。不为「整本一个块」开后门。

块过大时可以在单元内部再按课时或段落拆开，但子块仍必须带同一个单元名。

### 3. 存储与检索验收

表（名称实现时确定）至少包含：元数据五元组、单元名、页码、正文、embedding。同一五元组再次入库时按这五列删除再插入。

验收查询：过滤 `小学 / 一年级 / 数学 / 人教版 / 上册` 加单元名，返回该单元正文。Embedding 模型用环境变量配置，密钥不入库。向量维度与所选模型一致，并在表上建 pgvector 索引。

### 4. 本地 PDF

`book/` 保持现在的目录习惯（学段/科目/版本/文件名），但写入根 `.gitignore`。命令接收显式 PDF 路径，不从目录名猜测年级，避免文件名格式不统一时入错库。

## Risks / Trade-offs

- **[Risk] 数学课本版式导致单元标题识别失败** → 第一本失败即停止并保留样例输出，不写入半本脏数据
- **[Risk] 教材 PDF 误提交** → 本 change 把 `book/` 加入 `.gitignore`；已跟踪的文件在实现时从索引移除（保留工作区文件）
- **[Trade-off] 入库命令和 API 同仓库** → 依赖好共享；它不随 uvicorn 启动

## Migration Plan

- 空库直接建表
- 无历史向量需要迁移
- 若一年级上册试跑失败，删掉该书五元组对应的行即可重来

## Open Questions

- Embedding 用哪一家、哪一个模型，在实现时按已有 API key 选定，不改变切分与表结构的字段含义
