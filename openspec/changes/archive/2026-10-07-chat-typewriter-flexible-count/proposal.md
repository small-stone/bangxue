# Proposal

## Why

对话出题现在会卡在「正在理解你的需求…」，回复整段一次性出现，没有打字机感；题量又被钉死在 10/15/20/30，家长说「12 道」会被收成 10。需要让方式 B 的回复可流式展示，并按家长说的题量出题（上限 100）。

## What Changes

- 对话页助手回复改为**打字机效果**：SSE 增量追加气泡文字；出题等待时仍可显示进度，但最终回复不再整段蹦出。
- 方式 B 题量改为 **1–100 的任意正整数**；解析到的题量按原数出题，不再就近收到 10/15/20/30。超过 100 时拒绝或追问，不静默截断成 100（实现时二选一并在 design 写死）。
- 更新完整性判断与追问文案：不再暗示只能选 10/15/20/30。
- 方式 A 教材选题页的题量芯片**本期不改**（仍为 10/15/20/30）。

## Capabilities

### New Capabilities

- （无）

### Modified Capabilities

- `chat-generation`: 增加助手回复打字机展示；方式 B 题量支持 1–100。
- `flow-judgment`: 题量完整性判断与追问文案对齐任意题量（不再限定四档）。

## Impact

- **前端**：`Chat.tsx` 消费 `token`（或等价增量事件），边收边渲染；进度与草稿预览时序调整。
- **FastAPI**：`/api/chat/.../messages` 在出题完成后按块推送助手文本（可后端切块或前端本地打字机；design 选定一种）；长耗时仍靠进度事件，超时沿用现有长请求约定。
- **Agent B / Jev**：聊天出题与 count 校验、题量提取逻辑；方式 A 出题图与教材 Config 芯片不动。
- **数据**：无新表；确认后的 quiz 仍写入现有 store，`count` 可为任意 1–100。

## Non-goals

- 不做题目预览卡片的逐题打字机。
- 不放开方式 A 的四档题量。
- 不接入真实 TypeSafe 远程 Jev（本地封闭判断可改文案与 count 规则）。
- 不引入独立 Agent 服务或任务队列。
